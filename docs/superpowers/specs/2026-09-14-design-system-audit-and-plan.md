# Aho Farms website — Design audit & refinement plan

**Round 1 deliverable · 2026-09-14 · status: awaiting CEO sign-off before Round 2**

Scope: all 26 pages of `ahofarms-website` (`main`, commit `219fc1e`), reviewed
at desktop (1440), tablet (820) and mobile (390). Method: token/CSS extraction
across every page, a same-origin browser probe of every page at the three
widths (overflow, computed type, buttons, section rhythm, touch targets), and
full-page screenshots of 13 representative pages at desktop plus index / about
/ news / prescribers / contact at mobile and index at tablet. The probe script
is reusable for the Round 2 QA pass.

The governing documents remain `DESIGN-BASELINE.md` (2026-09-01) and the
2026-09-10 chrome brief. Nothing below proposes a new brand — it proposes
finishing the systemisation those two briefs started.

---

## 0 · Executive summary

**The site is two websites wearing one header and footer.**

| Family | Pages | Look |
|---|---|---|
| **"v6" cinematic** (10) | index, about, origins, team, tohu, cultivation, quality, products, board, business | void-black canvas, inset rounded flax/earth plates, gold accent, Cormorant display at 96–102 px, editorial rhythm |
| **"v3" template** (16) | news, contact, kaupapa, social-impact, investors, prescribers, pharmacies, export-partners, privacy, terms, disclaimer, 404, 4 × portals | blue-teal "night" (#1a2426) heroes, flat white / #f4f6f6 section stripes, 4–8 px cards with drop shadows, teal buttons and icons, headings at 56–68 px |

Everything the brief asks for — hierarchy, spacing, typography, colour
discipline, responsive behaviour — is inconsistent **primarily because of this
split**, not because of dozens of small slips. The single highest-value move is
therefore to bring the 16 v3 pages onto the v6 token set and plate grammar
(keeping their content and structure), and to put the shared tokens,
navigation CSS and component styles in the one stylesheet every page already
loads (`assets/aho-chrome.css`) instead of 26 inline copies.

Second: **teal and gold currently mix on the same row on almost every page** —
the header alone has a gold active label, teal hover states and a teal
coloured-wordmark hover; the Connect button has a gold icon and a teal hover;
professional pages put the gold `btn-primary` inside teal-night heroes next to
teal icons. The chrome layer already has the mechanism to fix this
(`--aho-accent` + `<html data-palette="teal">`) but no page uses it. The plan
assigns every page to one palette and makes every accent role read the
palette variable.

Third: **tablet is a stretched phone.** At 820 px the homepage is *taller*
than at 390 px (12,923 vs 11,206 px) because single-column mobile layouts are
combined with desktop spacing and full-height images. Mobile itself is
generally sound apart from touch-target sizes and some over-generous gaps.

Fourth: the **mobile navigation is an accordion** (sub-pages hidden until a
parent is tapped) with no wordmark and no social links — the opposite of the
brief. This is a contained change because the markup is generated by
`scripts/render-nav.js`.

Fifth: **a "What's New" page is feasible and cheap.** Verified channels:
LinkedIn (company page live), Instagram `@aho_farms_nz` (exists; profile is
age-restricted so it cannot be previewed logged-out), Facebook (URL supplied
by the CEO 2026-09-11, not independently verifiable), **TikTok: no account
found** — needs confirming or dropping. Recommended feed service: **Behold**
(JSON feed rendered in our own markup; handles the 60-day Instagram token
refresh; CDN-optimised WebP; $0 to start, US$10/mo to remove the hover logo
and lift the 1,200-view cap).

Decisions the CEO owns are collected in §15. Everything else is proposed as
implementation detail to be carried out in Round 2.

## 1 · Design system

### 1.1 Two token families, both duplicated into every page
*What:* Every page carries its own `:root` block. v6 pages define 45 tokens
(`--night:#0f1a18`, `--s1…--s9`, `--plate-r`, glass tokens…). v3 pages define
a different 10–19-token set (`--night:#1a2426`, `--night-mid`, `--card-border`,
`--radius-btn`…) plus a second stamped `:root` with `--gold/--s1…--s7`. The
shared `aho-chrome.css` adds a third, prefixed set (`--aho-*`).
*Why it matters:* the same word (`--night`) means two different colours; a
global change needs 26 edits; the chrome file has to fight page CSS with
`!important` (30–40 per v6 page).
*Recommendation (global):* one token layer in `aho-chrome.css` — colour,
type scale, spacing scale, radii, container, section padding, motion. Page
`:root` blocks are reduced to aliases of the shared tokens (`--night:
var(--aho-ink)`), so page CSS keeps working while every value has one source.
*Pages:* all 26.

### 1.2 Navigation CSS and JS live in every page
*What:* the header/drawer/dropdown CSS (≈68 rules) and the two nav scripts are
inline in all 26 pages; only the markup is generated.
*Recommendation (global):* move nav CSS into `aho-chrome.css` and nav JS into
`aho-chrome.js`; `propagate-chrome.js` already stamps both. Delete the inline
copies. This is also what makes the mobile-nav change (§7) a one-file edit.

### 1.3 No component vocabulary
*What:* buttons exist as `.btn.btn-primary`, `.btn-teal`, `.btn-teal-full`,
`.btn-gold`, `.btn-outline`, `.th-btn`, `.pr-card-cta`, `.btn-back`,
`.btn-logout`, `.btn-nda`, `.btn-submit`, `.cl-car-btn` (12 specs). Cards
exist as `.card`, `.ncard`, `.pr-card`, `.contact-card`, `.news-card`,
`.thesis-card`, `.team-card`, `.stat-card`, `.quick-card`, `.evidence-card`,
`.obligation-card`, `.commitment-card`, `.market-card`, `.portal-card`,
`.metric-card`, `.product-card` (16 specs). Eyebrows, stats, dividers, form
fields, notices and icons are re-declared per page.
*Recommendation (global):* a small shared component set in the chrome file —
`.btn` (+ `--primary`, `--secondary`, `--ghost`, `--sm`), `.card`, `.eyebrow`,
`.stat`, `.field`, `.notice`, `.hairline`, `.icon` — and page classes become
thin extensions. Where a page has a genuinely bespoke component (the homepage
constellation, the tohu principle plate) it stays bespoke.

### 1.4 Chrome overrides via `!important`
*What:* 11 `!important` on v3 pages, 30–40 on v6 pages, mostly the chrome
layer winning ties against inline page CSS.
*Recommendation (global):* once tokens and nav CSS move out of the pages, the
overrides can be removed; the chrome sheet loads last and wins naturally.

## 3 · Typography

Families are consistent (Cormorant Garamond + Inter everywhere) — the problem
is scale, not typeface.

### 3.1 No type scale
*What:* distinct `font-size` declarations per page: quality 88, origins 79,
about 70, cultivation 63, products 51, team 48, tohu 47, index 42; v3 pages
13–26. Values include `13.5px`, `12.5px`, `0.56rem`, `0.62rem`, `10.88px`.
*Why:* similar elements differ page to page (see 3.2–3.4) and there is no way
to reason about hierarchy.
*Recommendation (global):* a nine-step scale as tokens (`--t-xs 0.6875rem`
… `--t-display clamp(3.5rem, 7vw, 6.4rem)`), fluid at the top end, fixed at
the bottom; every heading/eyebrow/body/caption maps to a step.

### 3.2 Body copy varies 14.4–17 px
v6 15.2/16 px · kaupapa/social-impact/investors/export-partners 17 px ·
prescribers/pharmacies 15 px · legal & 404 14.4 px · portals 13–13.5 px.
*Recommendation:* 16 px body everywhere (17 px allowed for editorial
long-form measures on light plates), 14 px for captions/meta, 13 px minimum
anywhere. Portals 14 px body.

### 3.3 Display sizes differ by family
h1: v6 96–102 px desktop; v3 56–68 px. h2: v6 49–78 px; v3 40–50 px.
*Recommendation:* v3 pages adopt the v6 display steps when rebuilt; page
heroes use `--t-display`; chapter heads `--t-h2`.

### 3.4 Weights
v6 pages lean on Inter 300 (34–42 declarations per page) for body and labels
on dark — thin sans on near-black reads low-contrast on non-retina screens;
v3 pages use 500/600. *Recommendation:* Inter 400 body, 500 labels/nav, 600
buttons/strong; 300 reserved for Cormorant display ≥ 40 px. Trim the Google
Fonts request from 12 styles to the 6 used.

### 3.5 Eyebrows / small caps
Sizes 0.5625–0.75 rem, tracking 0.12–0.22 em, weights 500–700, colours gold,
teal, silver, 45 % white. *Recommendation:* one `.eyebrow` (0.6875 rem / 600 /
0.16 em / accent) with a `--muted` variant.

### 3.6 Buttons
Six typographic specs (13 px 600 · 14 px 600 · 12.8 px 500 · 14 px 500 ·
10.9 px 700 0.2 em · 12 px 500). *Recommendation:* 13 px / 600 / 0.06 em
uppercase for all buttons; `--sm` 12 px.

### 3.7 Default UI font leaking
`button`, `select`, `input` are not reset, so carousel buttons, the burger,
the news filter pills and form selects render in Arial/system. *Fix (global):*
`button, input, select, textarea { font: inherit; }`.

### 3.8 Measure
Paragraph max-widths range 26–58 ch and 540–840 px. *Recommendation:* body
measure 60–66 ch, lead paragraphs 40–48 ch, stats/captions ≤ 34 ch.

## 4 · Spacing

### 4.1 Section padding has 20 values
40, 48, 54, 63, 64, 72, 80, 81, 90, 96, 99, 100, 104, 108, 120, 126, 140, 144,
148, 160 px (desktop). Hero top offsets alone use 120/140/144/148/160.
*Recommendation (global):* `--sec-y-sm clamp(48px, 6vw, 72px)`, `--sec-y
clamp(72px, 9vw, 120px)`, `--sec-y-lg clamp(96px, 12vw, 160px)`; hero top
offset = nav height + `--sec-y-sm`. The v6 `--s1…--s9` 8-px scale becomes the
site scale (`--s*` aliases kept).

### 4.2 Container widths
v6: 1280 everywhere. v3: 1280, 1200, 1180, 1160, 1100, 1000, 960 for section
inners, 540–840 for text blocks. *Recommendation:* `--aho-max 1280` +
`--aho-gutter 32/24/20`; narrow variants `--max-prose 760`, `--max-form 640`.

### 4.3 Vertical rhythm inside chapters
Heading→body gaps vary 12–48 px; card padding 20–40 px; grid gaps 16–64 px.
*Recommendation:* stack gaps from the 8-px scale — eyebrow→h 12, h→lead 24,
lead→body 32, body→CTA 40; card padding 28 (24 mobile); grid gap 24/32.

### 4.4 Excess whitespace (page-specific)
- **index** mobile/tablet: ~300 px dead space after "Follow the thread" before
  *The Aho Advantage*; ~200–500 px between intro copy and the *Te Whenua*
  plate; ~150 px between the portal list and *News*.
- **about** desktop: the *He mahi whai tikanga* plate leaves a half-plate of
  empty sand under a short text column (sticky image column taller than the
  text).
- **origins** desktop: *Te Aho* chapter has a full-viewport black gap above
  the founder banner (scroll-pinned scene) — acceptable as a designed pause
  but 2,552 px is long; cap at 100 vh.
- **contact / news / prescribers** heroes: 140–160 px top padding above a
  short heading produces a squat, empty block.

### 4.5 Cramped
- **quality**: four horizontal step-strips (*Harvest · Cure · Hand trim ·
  Process*, *Grower · Harvester · Trimmer · Processor*, *Clone … Sale*, then
  the dark *Cultivation … Traceability* row) in one page — same composition
  repeated, contrary to baseline §9.
- **news** cards at 390 px: 24 px padding, 18.4 px h3 wrapping to four lines.
- **portal** headers at 390 px: user block pushed off-canvas (see §8).

## 5 · Alignment

- **Containers:** v3 pages centre 1200/1160 px inners inside the 1280
  container, so their left edges sit 40–60 px inboard of the header wordmark
  and footer; v6 pages align to the wordmark. Fix via §4.2.
- **Hero copy:** v6 heroes left-align to the container; kaupapa / social /
  investors / legal heroes centre their headings. One rule: page heroes
  left-aligned (baseline: "no long centred paragraphs"); centred only for the
  short *Tūhono* closers and legal titles.
- **Plate radii on inset images:** about uses `calc(var(--plate-r)*0.55)`,
  cultivation 6 px, products 3/6 px, team 4 px, news 4 px, contact 8 px.
  One `--r-img` token.
- **Card grids:** equal-height cards are not enforced on news, contact and
  prescribers grids (bottom links float at different heights). `grid` +
  `align-items: stretch` + CTA pinned to the card bottom.
- **Stat blocks:** hero stats on prescribers/pharmacies (teal rule, Cormorant
  numeral) vs. index/about (gold hairline, oversized numeral) vs. investors
  (centred). One `.stat` component.
- **Buttons in a row:** gaps 8–24 px; secondary button baseline sits 2 px low
  on index (`btn-sm` beside `btn-primary`). One button height per size fixes
  it.

- **Reduced motion:** v3 pages only inherit the chrome's rule; page reveals,

  block that disables reveals/parallax/marquee and pauses autoplay.
- **Touch targets:** §9.
- **Alt text:** every `<img>` has `alt` (0 missing) — good; portrait
  placeholders on team.html are `figure`s, fine.
